## 1. Program Tracks

The program offers two pathways:

### No-Code Track
- Builds AI agent solutions without traditional programming.
- Uses UI-based tools such as:
  - n8n
  - NotebookLM
- Intended for learners who prefer visual workflow tools.

### Code Track
- Builds AI agent solutions using Python.
- Includes both:
  - Low-code options
  - Full-code options
- Best suited for learners interested in programming.

Both tracks are designed to achieve the same learning outcomes. The main difference is how the solutions are built.

## 5. Learning Outcomes

By the end of the program, learners should be able to develop five broad capabilities.

### 1. Understand the AI Landscape
Develop a clear understanding of:

- Artificial intelligence
- Machine learning
- Deep learning
- Generative AI
- Agentic AI

Learners should also be able to identify business problems that these technologies can address.

### 2. Apply Generative AI and RAG
Learn how to use:

- Large language models
- Retrieval-augmented generation (RAG)
- Organizational knowledge
- Content automation
- Workflow automation

The goal is to improve productivity and streamline repetitive business processes.

### 3. Build Context-Aware Single-Agent Systems
Learn how to create agents that use:

- Tools
- Memory
- External systems
- Persistent context

These agents should be able to retain information and perform tasks with greater independence.

### 4. Implement Planning and Reasoning
Learn how agents can:

- Break complex objectives into smaller tasks
- Select appropriate actions
- Adapt when conditions change
- Manage dynamic workflows

### 5. Design Multi-Agent Ecosystems
Progress from single-agent systems to systems in which multiple specialized agents collaborate toward a shared goal.

Learners will also evaluate systems for:

- Scalability
- Transparency
- Reliability
- Safety
- Enterprise readiness

## 7. Mentor’s View of Agentic AI

A simple working definition presented during the session was:

> An agent is a large language model with access to tools and memory.

More advanced agentic systems are built by adding:

- Multiple agents
- Sub-agents
- Orchestration
- Planning
- Greater autonomy
- External integrations

The mentor emphasized that new techniques will continue to build on the same foundations:

- How LLMs work
- How tools are called
- How memory is used
- How multiple agents coordinate

---

## 8. Agentic AI Compared with Claude or Copilot

Tools such as Claude and Copilot can help developers build software or generate code.

Agentic AI is more focused on creating systems that perform work for end users through coordinated agents.

### Healthcare Appeals Example

A hospital responding to an insurance claim denial could use several agents:

- One agent gathers patient labs and vital records.
- Another processes documents.
- Another retrieves additional case information.
- An orchestrator combines the results.
- The final system drafts an appeal letter.

The value comes from decomposing a complex workflow into specialized tasks and coordinating the results.

---

## 9. Coding Experience

The mentor stated that extensive coding experience may not be required to begin building agentic AI systems because AI tools can now generate much of the code.

However, coding knowledge remains valuable for:

- Understanding system behavior
- Reviewing generated code
- Debugging
- Architecture
- Security
- Reliability
- Scaling
- Maintenance

The industry is increasingly placing value on:

- Product thinking
- Business and domain knowledge
- User experience
- System design
- Understanding customer needs
- Connecting technical solutions to real business outcomes

The mentor referenced the growing importance of roles such as the forward-deployed engineer, which combine technical implementation with customer and product understanding.

## 13. Flipped Classroom Model

The program follows a flipped classroom approach.

### Before the Live Session
Learners should:

- Watch recorded lectures
- Complete readings
- Work through practice exercises
- Review the weekly concepts

### During the Mentored Learning Session
The session generally includes:

- A brief conceptual review
- A business case study
- Hands-on discussion
- Industry insight
- Q&A and doubt resolution

### Why This Model Is Used
It allows learners to:

- Study at their own pace
- Practice before class
- Use live sessions for application
- Ask more informed questions
- Learn directly from an industry expert

1. Watch the recorded lectures.
2. Complete readings and hands-on practice.
3. Attend the mentored learning session.
4. Work through the case study.
5. Clarify questions.
6. Submit the graded assessment by the deadline.

- New content is generally released every Thursday.
- Learners have approximately one week to complete it.

- Weekly quizzes are generally due by Sunday at the end of the day.
- Each course ends with a project week.
- A project Q&A session is held on Saturday during project week.

## 15. Assessments and Grading

A minimum score of **60% in each module** is required for successful completion.

### Grade Breakdown

| Component | Weight |
|---|---:|
| Weekly quizzes | 30% |
| Course project | 60% |
| Mentored-session attendance | 10% |

### Projects

Each module includes a business-focused project.

#### Low-Code Version
Learners receive:

- A partially completed notebook
- Code templates
- Blanks to complete

Learners must:

- Fill in the missing sections
- Run the code
- Analyze the results
- Submit a business presentation containing insights and recommendations

#### Full-Code Version
Learners must:

- Write the code from scratch
- Solve the business problem
- Submit the completed notebook
- Provide insights and recommendations

Learners may select the version that best matches their goals.

### Project Deadline Policy
- Project extensions are not provided.
- Missing a project deadline may require completing a different project.

### Attendance
- Attendance at mentored learning sessions is mandatory.
- Attendance contributes 10% of the module grade.
